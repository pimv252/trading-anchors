# 公开锚点

这个仓库只做一件事：**公开记录一串根哈希**。

它不包含任何交易记录、持仓、金额或标的信息。每一行只有 32 字节的哈希、序号和一个时间。

## 为什么需要它

RFC 3161 时间戳（FreeTSA / DigiCert）能证明「某个哈希在某个时刻已经存在」，但它不知道你同时提交了几个哈希，也不知道你事后公布了哪一个。

于是存在这条路：开两条内容不同的链，各押一个方向，两条都给 TSA 盖章，事后只公布赢的那条。两个时间戳都是真的，验证都能通过，读者无从分辨。

把根哈希写进一个公开、可被复制、事后难以单方面删除的地方，这条路就堵上了：一旦有人 clone 过，你改历史就会被发现。

## 文件格式

`anchors.txt`，一行一条，按序号递增，只追加不改写：

```
2026-10-31T05:22:25Z  seq=38  226cfa3c0493b9e2be69ed4dd9747c652c8c4f2b3e39f447a792aa6fb47345ad  freetsa,digicert
```

| 字段 | 含义 |
|---|---|
| 第一列 | TSA 签发的时间（UTC） |
| `seq=N` | 账本中第 N 条的序号 |
| 第三列 | 该条记录的 SHA-256 哈希，即当时的链尾根哈希 |
| 第四列 | 为该哈希签发时间戳的 TSA |

## 第三方怎么验证

哈希本身不泄露内容，所以光看这个仓库你无法知道具体交易。但你可以验证两件事：

1. **哈希确实被第三方签过时间**——向对方索取对应的 `.tsr` 文件，用 `openssl ts -verify` 离线验证，不需要信任记录者。
2. **公开记录是连续的**——`seq` 必须从 1 递增且不缺号。若中间有断号，说明那一段没有被公开承诺过。

如果对方日后公布了完整账本，你可以自己重算哈希链，逐条比对本文件里的值。对不上，就说明账本被改过，或者公布的不是当初承诺的那条链。

## 局限

这个仓库能证明「承诺过哪条链」，不能证明「链里记录的是全部事实」。

哈希链只保证写进去的内容没被篡改，无法阻止漏记。要检验完整性，需要看账本里是否带有持仓数量与权益的定期快照，并用「状态差额 = 期间事件总和」的恒等式去对账。
